# ISL443E Course Requirements Checklist – Project Design and Management (ITU, 2026/2027 Fall)

This document maps the requirements of the ISL443E syllabus and the artifacts in the `TR_artifacts`
folder against the current state of the ICT project from Wrocław University of Science and Technology
(`ICT_Project` — "Integrated medical system supporting information management (EMR)", 4EDM, June 2026).

**Status legend:**

| Symbol | Meaning |
|--------|---------|
| ✅ | Requirement fulfilled / artifact ready |
| ⚠️ | Partially fulfilled – needs completion or adaptation to the ITU format |
| ❌ | Not implemented – must be created from scratch |
| ➖ | Not applicable to project artifacts (purely administrative / course activity) |

## 2. Project Proposal and Presentation (15% of the grade: 7.5% presentation + 7.5% report)

Requirements from the syllabus (week 7) and `Project Proposal Sample.pptx`:

### 2.1 Substantive components of the proposal

| # | Requirement | Status | State in the PWr project |
|---|-------------|--------|--------------------------|
| 2.1.1 | **Project Selection** – selection criteria, selection models, scoring | ⚠️ | `Rozdziały/project-idea.tex` — three EMR system variants (basic/optimal/extended), a comparison table of 20 criteria, selection of Variant II with justification. **No formal scoring model** with weighted criteria and point scoring, as required in week 3 of the syllabus; the variant assessment is qualitative (yes/partial/low…). To complete: weighted matrix + scoring + weight sensitivity analysis. |
| 2.1.2 | **Business Model Canvas** (or Lean Canvas / Social Business Model Canvas) | ❌ | No canvas of any kind. `Project Proposal Sample.pptx` shows exactly such a slide as mandatory. To build from scratch: 9 building blocks (customer segments, value proposition, channels, relationships, revenue streams, resources, key activities, partners, cost structure) – for a social project use the Social BMC variant. |
| 2.1.3 | **Value Proposition Canvas** (covered in week 1) | ❌ | Absent; required as a tool for working on the value proposition (customer profile map + gain/pain map). |
| 2.1.4 | **Elevator Pitch** | ❌ | Missing. The PWr presentation has 25 slides and the character of a technical report, not a pitch. To prepare: a concise narrative (problem → solution → market → value → team) in about 60–90 seconds. |
| 2.1.5 | **Draft WBS** (Work Breakdown Structure) | ❌ | No work breakdown structure. The closest element: the M0–M6 payment schedule in `kosztorys.tex` (milestones: contract, architecture, infrastructure, UAT, devices, pilot, go-live) – it is a milestone list, not a WBS. To build: a 2–3 level hierarchy (e.g. 1. Initiation → 2. Analysis → 3. Design → 4. Implementation → 5. Acceptance → 6. Closing) with work package identifiers. |
| 2.1.6 | **Project Organization** (project organizational structure) | ⚠️ | `work_table.tex` divides work among 6 people by report chapter. However, there is no **project organizational structure**: Project Manager role, functional teams, reporting lines, client (hospital) collaboration model. Some roles appear only as cost estimate line items (Project Manager, Architect, DevOps…) in CAPEX category A – these are roles of a fictional contractor, not the task division within the student team. To complete: organizational chart + description of project team roles. |
| 2.1.7 | **Stakeholder Analysis** | ✅ | `Rozdziały/empatyzacja.tex` — very extensive: stakeholder map (key players, main/potential users, dormant stakeholders, observers) and 10 personas (director, board, IT staff, physician, medical student, nurse, 72-y.o. patient, 35-y.o. patient, malicious user, startup CEO, media, ministry) with profiles, expectations, concerns and project implications. Exceeds the ITU requirement – only format adaptation needed (influence/engagement matrix). |
| 2.1.8 | **RACI matrix** | ❌ | Missing. `work_table.tex` names the chapter author (de facto Responsible), but does not provide R (Responsible), A (Accountable), C (Consulted), I (Informed) for project tasks/activities. To build: rows = WBS work packages, columns = team members (7–8 people), cells = R/A/C/I. |
| 2.1.9 | **Team qualifications** | ❌ | No section describing members' competencies (education, technical skills, experience, certifications, project roles). To add: a table or profile for each member – why this team is capable of delivering the project. |
| 2.1.10 | **Business Plan Submission** (week 2 – template from Ninova) | ❌ | Missing. The template in `Project Proposal Sample.pptx` suggests the structure: group/company name, need/problem, canvas, competitor benchmark. |
| 2.1.11 | **Benchmark / competitor analysis** (slide 7 of the sample: Your company vs competitors, feature comparison) | ⚠️ | `kosztorys.tex` contains EMR/EHR implementation benchmarks (Oracle Cerner, Epic, cost per bed with PPP correction) – this is a **cost** benchmark, not a product/competitor comparison. To complete: feature-based comparison with real competitors/solutions (e.g. Comarch, Asseco, dedicated EMR systems). |
| 2.1.12 | **Proposal presentation with every member speaking; mandatory attendance** | ⚠️ | `prezentacja/ict_prezentacja.pdf` exists (25 slides) and the closing slide lists 6 people. It is unknown who actually presented and whether everyone spoke; the format is not the ITU "proposal presentation". When transferring: shorten to proposal format, assign segments, prepare speaking parts for each member. |
